# From "I need an IDS for Kistefos" to a checker with BCF, an object panel and three skins

Four days, `1a1e43f` → `ada4c1a`, every step deployed to https://ifc-check.skiplum.com as it
landed. edkjo, 2026-09-21: *"nobody is using this, so straight to prod"* — no staging, verify
live, fix forward.

## What now exists that did not

**Code lists as bundled lookups.** NS 3457-8, 909 codes from
`resources/standards/ns3457/ns3457_pdf_extract.json`, generated by `scripts/gen-codelists.py`
with provenance and a code-by-code cross-check against the reviewed table. The check flags codes
the model carries that the list does not have.

**The `code-lookup` rule is project config, not a hardcoded convention.** edkjo killed the first
design on sight: *"We need to configure where it reads them from. That's part of the project
config."* So a rule carries list · target (occurrence/type) · source (attribute | property | classification)
· an extraction regex, and the Kistefos settings live in `examples/knm.ruleset.json`.

**Setup page** with the four POFIN mappings — Systemkode, Komponentklasse, Prosesstatuskode (MMI),
Duplikat objekt — plus Etasjeoppsett (config floors, name + kote). `Duplikat objekt` is a SCOPE
FILTER, not a data check: *"The important thing is that objects are filtered out if they are not in
the model scope. No need to report on bad data for reference objects as long as they can be
identified as such."* Reference objects are removed from every other rule's selection, and the
count of excluded objects is printed so the filter is never silent.

**BCF 2.1 export**, validated against the vendored buildingSMART XSDs and parsed back by
`bcf-client`. Topics are model × failing check × storey, ≤ 500 GUIDs (Dalux's limit, a field in
the UI, not a constant). An oversize storey splits by IfcSpace, and only for DISCRETE objects:
*"'rom' needs to be for the 'discrete' objects, not the massing objects."* Discrete = centre in
the space, ≥ 0.5 of its box inside, touching no other space, ≤ 0.9 × the space height. Thresholds
measured on HI90, where every terminal sits at ≤ 0.77 of room height and every wall at ≥ 1.10.
HI90 went 285 → 89 topics.

**Tabs, and a board that stops being stunted.** *"We've moved into a place where we're trying to do
too many things in one page."* Kontroll (bento) · Innhold (census + type ledger) · Graf. The
BentoGrid took the track from the smaller of width and height, so on every 16:9 screen the height
won and every tile shrank below its content — that was the "KNM…" headers and the hidden rules.
Track is now width-derived, the page scrolls, and the row unit grows toward the viewport height
only as far as the placed tiles' aspect bounds allow. `scripts/viewport-gate.mjs` asserts 14
viewports × both tabs × one and three models, and prints the leftover band rather than hiding it.

**The click model, settled.** The UI isolates, the viewer highlights — his ifcfast-site rule,
now written in AGENTS.md. Every row that is a set isolates; a row in the band is one element;
`Element` ANDs with the set chip; a check that could not run makes NO chip, because filtering to
an empty scene reports "not answered" as "nothing found".

**The object panel** (in the band, opened by a selection): lead KPI cards, then Attributter ·
Relasjoner (classification lives here — it arrives through `IfcRelAssociatesClassification`, same
as material) · Egenskaper, one tab per pset, standard `Pset_*` before project sets · Beregnet.
Purpose, from edkjo: *"reveal and express what the IFC is saying to non-technical users"*, and the
hard rule under it: *"I hate opinionated viewers that hide data … I like opinionated
grouping/tabs, not what to show."* Every row carries a plain Norwegian label with the IFC term
beside it, and every category the engine cannot answer says so instead of being left out.

**Beregnet** reuses `placementOf` — extracted out of `checkMeshPlacement`, one hub, one cutoff,
one tolerance — so the panel and the check cannot disagree. Which storey the geometry sits in,
height over the stated kote, box, distance from the main body, triangles, room.

## Two engine findings worth carrying

**ifcfast#183 was never blocking.** ifcfast `main` has exposed `psetsJson` / `quantitiesJson` /
`materialsJson` / `classificationsJson` since v0.5.3; ifc-check's vendored module was v0.5.1. Weeks
of `not_evaluable` came from a stale vendor directory, not a missing capability. Branch
`feat/wasm-type-objects-183` (`6a16c16`, EdvardGK/ifcfast, pushed, unmerged) adds the one real
gap: `typeObjectsJson()` and `type_guid` on product rows, verified row-for-row against
ifcopenshell on four KNM models. Vendored here at `5f555f2`; PROVENANCE says loudly that it is a
BRANCH head, because rebuilding from `main` silently drops both.

**Zoom saturated because the radius window came from the model.** `[extent×0.002, extent×50]` — on
KNM_ARK 0.36 m … 8 961 m. Framing one element puts the camera outside it, so a zoom-in clamped
outward and every later tick returned early. Fix: an explicit frame widens the window
(`Turntable.allow`), and the stops absorb a camera already outside them. Measured 12.42 → 4.76 m
over six ticks, 44 ticks back out past the model view.

## The verdict that reopened everything

2026-09-23, after the layout work landed: *"our problem now is that the UIUX is really ugly and old
looking. We need this to be modern, snappy and impressive"* … *"the graph for instance needs to be
cool and smooth."* Structure accepted, visual language rejected — the cream/hairline/gold-caps
vocabulary mirrored from sprucelab. Recorded in `resources/design-system/data-workspace.md`.

Three directions, live under `#design=a|b|c`, argued off his own record rather than a generic
triple: **a Instrument** (graphite, mono, the register he put into production on ifcfast-site),
**b Papir** (ink on paper, Schibsted Grotesk, the standing canon), **c Smash** (rust field,
frosted panels, thefinanceapp's loud register). Status stays a traffic light in all three; gold
caps retired. The graph is a real simulation now — velocity Verlet, reheat per gesture, drag,
zoom about the pointer, collision-ranked labels, no d3 (180 nodes at 0.140 ms/tick).

Awaiting his pick. On ifcfast-site he took A+B combined, not one of three.
